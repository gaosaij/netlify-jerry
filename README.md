# netlify-jerry

个人文章站。除了原有的文章列表，还支持：

- **英文文章翻译**：一段英文、一段中文的对照阅读，长文分多次翻译，翻译到哪页面就显示到哪。
- **搬运网页**：填网址，服务器自动抓取并翻译，不用再下载 HTML 重新发布。
- **上传文件**：`.html` / `.md` / `.txt` / `.pdf`，或直接粘贴文本。
- **PDF 识别**：用 MinerU 云端 OCR 把 PDF（含扫描版）转成文字、表格、公式和图片，再翻译。

## 一、部署（只做一次）

1. 把仓库里的改动传到 GitHub：新增 `admin/`、`netlify/` 文件夹，以及更新 `articles.json`、`build.js`、`index.template.html`、`netlify.toml`、`package.json`、`package-lock.json`。`tests/` 不用传。
2. Netlify 会自动构建。构建时会安装依赖（`@netlify/blobs`、`cheerio`、`marked`），并把 `netlify/functions/` 部署为云函数。

## 二、配置环境变量（只做一次）

Netlify 后台 → **Site configuration → Environment variables → Add a variable**，添加下面几项：

| 变量 | 必填 | 说明 |
|---|---|---|
| `OPENAI_API_KEY` | 是 | 大模型 API 密钥 |
| `OPENAI_BASE_URL` | 否 | 接口地址，默认 `https://api.openai.com/v1`。用其它 OpenAI 兼容服务时改成对应地址，例如 DeepSeek 为 `https://api.deepseek.com/v1` |
| `OPENAI_MODEL` | 否 | 模型名，默认 `gpt-4o-mini`。想要更好的译文可换更大的模型 |
| `ADMIN_PASSWORD` | 是 | 管理页密码，自己定一个。上传、搬运、翻译、删除都要用它 |
| `MINERU_API_TOKEN` | 处理 PDF 时需要 | MinerU 的 API Token（见下方“MinerU 配置”） |
| `MINERU_MODEL_VERSION` | 否 | MinerU 模型版本，默认 `vlm`，也可填 `pipeline` |
| `FETCH_USER_AGENT` | 抓 SEC 等网站时需要 | 抓取网页和图片时使用的 User-Agent。SEC 要求写明身份和联系邮箱，否则返回 403，例如 `你的名字 你的邮箱@example.com` |
| `AUTO_TRANSLATE_MAX_CHARS` | 否 | 待翻译字符数超过它就不自动翻译，等你确认；默认 `300000` |

### MinerU 配置（PDF 识别）

1. 打开 https://mineru.net ，登录后进入 **API 管理** 页面（https://mineru.net/apiManage），自定义创建一个 Token，复制下来。
2. 在 Netlify 环境变量里添加 `MINERU_API_TOKEN`，值就是这个 Token（不需要加 `Bearer`，程序会自动加）。
3. 重新部署。管理页顶部会显示“PDF 识别（MinerU）已配置”。

不配置 `MINERU_API_TOKEN` 也能用：PDF 会退回到浏览器里本地提取文字（不支持扫描版）。

**加完变量后必须重新部署才生效**：Deploys → Trigger deploy → Deploy site。

### 检查是否配好

打开 `https://你的站点/admin/`，输入 `ADMIN_PASSWORD`。页面顶部会显示：

- “翻译接口已配置：模型名（接口地址）”：正常；
- “⚠ 还没有配置 OPENAI_API_KEY”：密钥没配好或还没重新部署。此时文章仍能保存，配好后点“开始翻译”即可。

## 三、日常使用

打开 `/admin/` 登录（浏览器会记住密码）。

### 搬运网页

填文章网址，选择：

- **搬运并翻译**（默认）：保留原网页的样式和图片，每个英文段落后面紧跟同样式的中文段落。
- **仅搬运**：原样保存网页，不翻译。图片和样式仍引用原站，原站下线后会失效。

### 上传文章

- `.html`：和搬运一样，保留原样式并逐段翻译。
- `.md` / `.txt` / 粘贴文本：用站内统一的对照排版。
- `.pdf`：在浏览器里提取文字，只上传提取出的段落（见下方“PDF 说明”）。

### 用 SingleFile 保存网页再上传（推荐用于需要登录、靠 JS 渲染、或原站可能下线的网页）

[SingleFile](https://github.com/gildas-lormeau/SingleFile) 是浏览器扩展，在真实浏览器里把渲染好的网页保存成单个 `.html` 文件，图片、字体、样式都内联进去。保存后在管理页上传这个 `.html`：

- **超过 3MB 自动分块上传**（每块 4MB），最大 80MB，处理在后台进行，状态显示“正在抓取解析”。
- **内联的图片和字体会被拆出来**单独保存（页面里改成指向本站的地址，同样的图片只存一份），所以保存下来的网页只剩文字和样式，页面很快；删除文章时会一并删掉。
- 原页面的样式保留，每段英文后面紧跟同样式的中文，和直接搬运网址时一样；SingleFile 写在文件开头的原网址会被记成来源。
- 保存的网页如果里面有整页大图，配置了 `MINERU_API_TOKEN` 时同样会识别图里的文字再翻译。
- 提示：SingleFile 是 AGPL 许可，在自己电脑上用它保存网页没有问题；本站不包含它的代码，只处理它生成的文件。

“上传后自动翻译”取消勾选，则只保存不翻译，之后可在列表里点“开始翻译”。

### 站内已有文章

“站内已有文章”区列出仓库 `articles/` 下的文章：

- 点“翻译”翻译单篇，或点“翻译全部未翻译的”。
- 翻译后，首页自动隐藏英文原版，只显示对照版。
- 不想翻译的文章，在 `articles.json` 里给它加 `"translate": false`（“How People Use ChatGPT”已设置）。

### 查看进度

- 文章页 `/t/文章名`：翻译中顶部显示进度，每 8 秒自动更新，不会打断阅读位置。
- 管理页“所有文章”：显示每篇的状态和进度条；出错或中断时有“继续翻译”按钮，已翻译的部分不会丢。
- 首页：显示翻译中的文章和进度。

### 自动判断：已有中文就不翻译

上传或搬运时会检测文章是否已有中文（含中文的段落占 20% 以上，或全文中文占比 12% 以上）。已有中文的文章按原样保存，不调用模型。同一篇文章重复上传或搬运也会被拦住。

## 四、PDF 转出来的网页（如 SEC 备案文件）

有些网页本身就是 PDF 转成的 HTML：每一行文字都是一个绝对定位的小块，没有 `<p>`，句子被切成一行行，还夹着页眉、页码，整页插图直接做成大图片（文字在图里）。搬运这类网页时会自动：

1. **识别并还原段落**：按坐标把行合成标题和段落，去掉重复的页眉页脚和页码，接上连字符断行，合并跨页的段落。（在 SEC 的 S-1 文件上试过：31,739 个行片段还原成约 3,450 个段落。）
2. **整页图片 OCR**：接近一页纸大小的图片会由服务器抓下来（用 `FETCH_USER_AGENT`）交给 MinerU 识别，识别出的文字放在图片后面，一段英文一段中文。普通图表不识别。需要配置 `MINERU_API_TOKEN`；没配置时会在文章备注里提示。
3. **文档版式（尽量和原页面一样）**：每个原页面显示成一张白色卡片、灰色背景；段落保留原来的字体、字号、加粗、斜体、颜色，译文紧跟在后面、样式相同（蓝色）；**表格原样保留**（底色、边线、缩进、数字对齐都不变），下面紧跟一个“中文对照”表，只翻译文字单元格、数字不动；图片按页放回原位。
4. **大网页走后台**：超过约 3MB 的网页先建占位，状态显示“正在抓取解析”，后台函数处理完再接着 OCR 和翻译，上限 40MB。每个原页面一张卡片，每屏显示 20 页，页面顶部和底部有“上一部分 / 下一部分”；表格原始 HTML 单独存放，按需读取。
5. **超长文章先确认**：待翻译字符数超过 `AUTO_TRANSLATE_MAX_CHARS`（默认 30 万字符）时，不会自动开始翻译，管理页显示估算，确认后点“开始翻译”。比如 SEC 那份约 160 万字符、3,400 多段，用小模型也要约一两个小时。

## 五、长文是怎么翻译的

翻译在 Netlify 后台函数里进行，每轮同时翻译几批（每批约 3000 字符），每翻完一轮就把进度写回存储。单次运行接近 12 分钟时，会保存进度并自动重新启动，继续翻译剩下的部分，所以几百页的文章也能翻完。遇到限流（429）或服务端错误会自动退避重试；模型返回的段落数对不上时，会自动拆小重试。

## 六、PDF 说明

### 用 MinerU 识别（推荐，配置了 `MINERU_API_TOKEN` 时默认使用）

- **上传 PDF**：管理页选 `.pdf` 文件，保持勾选“PDF 用 MinerU 识别”。浏览器把文件按 4MB 分块传到服务器，后台再交给 MinerU。
- **搬运 PDF 网址**：在“搬运网页”里直接填 PDF 链接，程序会识别出是 PDF，让 MinerU 自己去下载。链接必须能公开访问；MinerU 访问国外网站（如 GitHub、AWS）可能超时，遇到这种情况请先下载再上传。
- **过程**：状态显示“OCR 识别中 x/y 页”，识别完自动开始翻译，进度和之前一样实时可见。
- **保留的内容**：标题、段落、表格、公式（以源码形式显示）、图片（保存在站点存储里）。
- **长文**：MinerU 单次最多 200 页，超过的 PDF 会按页码自动拆成多个任务，识别后按顺序合并。上传方式会自动读取页数；网址方式读不到页数，超过 200 页时会提示“页数超限”，请下载后改用上传。
- **出错**：管理页会显示 MinerU 返回的原因，点“继续识别”重试。
- **隐私**：PDF 会发送给 MinerU 云端处理。

### 不用 MinerU（取消勾选，或没配置令牌）

在浏览器里用 pdf.js 提取文字，只上传提取出的段落：

- 会去掉页眉、页码，接上连字符断行，合并跨页段落，按字号识别标题。
- 扫描版（图片）PDF 没有文字，无法提取；双栏论文栏序可能错乱。

想去掉这个本地提取功能：删除 `admin/pdf-extract.js`，再删掉 `admin/index.html` 里 `extractPdf` 相关代码。MinerU 识别不受影响。

## 七、限制与注意

- 直接上传的小文件（粘贴文本、3MB 以下的 HTML）走普通请求；更大的 HTML 和所有 PDF 都是分块上传，不受 Netlify 6MB 请求体限制。HTML 上限 80MB，PDF 上限 200MB（MinerU 的限制）。
- MinerU 每个账号每天有 1000 页的最高优先级额度，超出后识别会排队更慢；具体额度和限制以 MinerU 官网为准。
- 保存的文章在 Netlify Blobs 里，不在 GitHub 仓库中。删除站点或清空 Blobs 会丢失。
- 搬运时会去掉原网页的脚本（安全考虑），依赖脚本才能显示的内容可能不完整。
- “仅搬运”不会 OCR、不会翻译；不勾“自动翻译”的上传也不会 OCR。
- 只识别“逐行绝对定位 + 内联样式”的 PDF 转 HTML（EDGAR 备案文件即此类）。用 CSS 类写位置的转换器（如 pdf2htmlEX）暂不支持，遇到请把例子发我。
- 翻译会产生模型调用费用，长文请留意用量。
- `/admin/` 页面本身公开可访问，但所有写操作和管理接口都要 `ADMIN_PASSWORD`；`/admin/` 已设置 `noindex`，不会被搜索引擎收录。

## 八、本地测试（可选）

```bash
npm install
npm test
```

测试用的是本地模拟的 OpenAI 接口，不会产生费用。想在浏览器里看管理页：

```bash
node build.js
node tests/dev-server.mjs
```

然后打开 http://127.0.0.1:8790/admin/ ，密码 `test-pass`。

## 九、项目结构

```
admin/                  管理页（admin/pdf-extract.js 是 PDF 提取）
netlify/functions/
  api.mjs               接口：上传、搬运、翻译、删除、列表
  page.mjs              文章页 /t/文章名
  translate-background.mjs  后台分块翻译
  ocr-background.mjs    后台 OCR（MinerU）：PDF 和网页里的整页图片
  ingest-background.mjs 后台导入大网页
  lib/pdf-layout.cjs    行文字 → 段落的还原算法（服务器和浏览器共用）
  lib/                  存储、解析、翻译、渲染
articles/               手动上传到 GitHub 的静态文章
articles.json           文章标题、简介、置顶、是否翻译
build.js                构建：生成首页和站内文章清单
tests/                  自动化测试与本地模拟环境
```
